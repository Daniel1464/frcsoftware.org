A lot of the differences between commands v3 and commands v2 (especially on the syntax side)
can be found [here](/learning-course/stage1/stage1b/stage-overview/).
However, there are more
architectural differences between the 2 frameworks.

# Commands always run while disabled

In commands v3, commands can be scheduled and run even when the robot is disabled.

When `elevator.moveTo(Location.L4)` is running, the `Scheduler`
considers the `intake` and `wrist` to not be required by a command.
Their
default commands will run while the elevator is moving.

    This behavior is often referred to as "proxy-by-default".
</Aside>

# OpMode and Command scopes

Commands v3 introduces a new concept called scopes, which can exist at the **OpMode**, or **Command** level.

### Key Behaviors

1. Commands scheduled inside a parent command cancel automatically
   when the parent command ends.
   Similarly, commands scheduled during an OpMode cancel when that OpMode is disabled.
2. Trigger bindings created inside a command or active OpMode are scoped.
   When the parent command ends or the OpMode disables, the bindings will become inactive and cancel any commands they triggered.
